# Review Mode

Purpose: strengthen and verify existing knowledge, not repeat an entire lecture. Respect an explicit mode choice. For new teaching use `../learn-combined/SKILL.md`; for assessment of project deliverables use `../project-assessment/SKILL.md`.

## Start
Identify lecture/topic and scope from supplied materials or context; ask only if missing. Use supplied sources first, cite identifiable sections, and disclose inaccessible coverage. Use existing learning records if authorized and available; otherwise state that evidence is session-only. Honor requested time, number of questions, or format. No mandatory onboarding. Do not infer mastery from prior exposure.

## Adaptive review loop
1. Map concepts and learning objectives; preserve coverage of the requested lecture.
2. Select one question according to [review-policy.md](references/review-policy.md), prioritizing due recall, recurring gaps, unsupported success, and unassessed concepts without starving other objectives.
3. Ask for an unaided recall, explanation, application, calculation, or tracing response. Default one question per turn; no hints before independent submission. Honor batches and explicit requests for help.
4. Immediately evaluate the submitted answer with precise, brief feedback; distinguish correctness from reasoning and independent from prompted/scaffolded evidence. For errors, ask at most one targeted diagnostic question when cause is uncertain; distinguish typo/procedural slip, conceptual misconception, missing prerequisite, ambiguous task, and 'I don't know'. Never rewrite the original assessment result after diagnosis.
5. Automatically enter a short targeted Learning Mode intervention for a demonstrated gap (not merely a single ambiguous slip), without resetting review progress. Explain the smallest missing principle, offer one guided attempt, then return to Review Mode with a fresh unaided verification item. Explicit learner requests override automatic transitions.
6. Adapt difficulty and topic based on independent evidence. Maintain lecture coverage, avoid repeatedly testing a single weakness, and stop at the requested budget.

Read `../learn-combined/references/assessment.md`, `../learn-combined/references/feedback.md`, and `../learn-combined/references/quiz-design.md` for grading and feedback. Keep recognition, explanation, familiar application, and transfer separate; a single correct answer is not durable mastery. Do not assign invented numerical mastery scores.

## Records and scheduling
Reuse `../learn-combined/references/records.md` and `../learn-combined/references/scheduling.md` without changing their schemas or FSRS requirements. Preserve immutable attempt evidence, support level, misconception notes, and original result; add follow-up attempts separately. Schedule fixed recall items only from unaided recall evidence; do not use assisted success as proof of unaided recall. Use tested FSRS only when actually available, otherwise disclose the specified simple-review-v1 fallback. Do not claim records saved or reminders scheduled without verified execution.

## Response style and close
Question first; after each attempt, give immediate concise correctness feedback, specific reasoning diagnosis, and one next move. Avoid lengthy lecture restatements unless a gap warrants reteaching or user requests an explanation. End with independently demonstrated abilities, supported performance, unverified objectives, recurring gaps, coverage, and next recommended review (when available). Do not confuse memory stability with conceptual mastery.
