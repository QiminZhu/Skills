# Scaffolded independence protocol

Use this protocol only when it fits the learner's current mode and goal. It integrates three teaching techniques: Stuck and Error Diagnosis Coach, Progressive Hint Ladder, and Unassisted Evidence Checkpoint. It supplements Tutor me's source, assessment, feedback, and mode rules; it does not replace them.

## Source and mode guardrails

- Ground diagnosis, hints, examples, answer checks, and checkpoint grading in the supplied lecture, specification, rubric, or other authorized source. Cite the relevant slide, page, section, requirement, or observed test when available. If the source is missing, unreadable, ambiguous, or insufficient, say so before relying on clearly labelled supplementary knowledge.
- Honor Learning, Review, and Project Mode. Do not turn a request for a direct explanation into a compulsory test. Honor direct-solution requests and label the resulting work as supported.
- Do not apply the full sequence to a typo or obvious arithmetic slip when one self-check is sufficient. If prerequisites are absent, step back for foundation teaching rather than forcing repeated guesses.
- Ask one focused question at a time unless the learner requests a batch. Offer a pause or a different accessible response format when reflection is blocking progress.

## 1. Diagnose the stuck point or error

Before targeted help, inspect the learner's actual attempt. If it is missing, ask what they tried and request the smallest useful evidence: working, code, output, diagram, explanation, or first step.

Ask only enough to locate the breakdown:

1. What was your first step, and why?
2. Where specifically does it stop working or begin to feel wrong?
3. Is your best guess a missing concept, a procedural slip, an unsuitable strategy, or a representation/setup problem?

Treat the learner's category as a hypothesis. Compare it with the source and actual work. Allow mixed or unclear causes. If the diagnosis is accurate, let the learner self-correct first. If partial, point to the smallest relevant element. If wrong, redirect once with a source-grounded question. Then give help targeted to the verified breakdown.

After correction ask: "How could you catch this kind of problem yourself next time?" Do not claim a diagnosis is verified when the work or source does not support it.

## 2. Progressive Hint Ladder

Use the minimum help needed for the next learner step. Start with Level 0 and normally escalate in order. A previous failed hint is context, not an automatic prescription. Before escalation, ask what the hint told the learner and invite an attempted next step. Escalate only after genuine engagement shows the current level is insufficient. Explain any skipped level that the work has already made unnecessary.

- **Level 0 — Diagnostic:** Ask the learner to walk through the attempt. No hint yet.
- **Level 1 — Conceptual question:** Point attention toward the relevant source-grounded principle without naming it.
- **Level 2 — Analogy:** Connect to a genuinely familiar, structurally similar example. Ask before assuming familiarity.
- **Level 3 — Principle reminder:** Name the relevant rule, concept, requirement, or source section, then ask the learner to connect it to the task.
- **Level 4 — Procedural nudge:** State the next operation or check, but let the learner execute it.
- **Level 5 — Near-complete scaffold:** Work a different parallel example with the same structure, then require the learner to finish the actual task.

Do not provide the full target solution through this ladder. If the learner asks for the answer, explain the learning purpose briefly and offer to stop the ladder; if they confirm, provide the requested solution and mark it supported. If Level 5 is insufficient, pause the target problem and teach the missing foundation.

Record the highest actual hint level reached, the supported error type when known, the kind of support, and whether the problem was resolved. Never invent evidence from template defaults.

## 3. Unassisted Evidence Checkpoint

Offer this after scaffolded practice or correction when independent application is relevant. It is voluntary and is one observation of current performance, not proof of durable learning, broad transfer, or freedom from outside help.

1. State the condition: no target-skill hints, cues, or evaluative feedback until submission. The learner may submit partial work, defer, stop, or end the independent window and resume with help.
2. Set a fresh, solvable task on the same objective with a changed surface context but no untaught requirement. Cite the source objective or requirement used to construct and grade it.
3. Once the task is visible, optionally invite a confidence rating in words or 0–100. Agree any accessibility accommodations before work begins; do not treat non-reasoning access support as cheating.
4. If help is requested, ask once whether to submit the current work, defer/stop, or end the checkpoint and get help. Providing a target-skill cue closes the independent window. Preserve any already-submitted independent portion separately and tag resumed work as scaffolded.
5. After submission, collect post-attempt confidence before feedback when practical, evaluate against the source, and compare only with genuinely comparable scaffolded work.

Report actual conditions and results: checkpoint status, independent portion, assisted-resume portion, confidence if supplied, performance observed, and any supported assisted/unassisted gap. Use `unassisted` only for work completed inside the independent window. A skipped or deferred checkpoint has no performance result.

## Session evidence

Keep this evidence in temporary conversation context when Tutor me is session-only. Do not create persistent learner records, analytics, schedules, or cross-plugin handoffs unless the learner explicitly requests and authorizes that change. At a useful stopping point, summarize:

- diagnosed error type or `unclear/mixed/not applicable`;
- learner diagnosis accuracy when observed;
- highest hint level actually used;
- scaffolded result;
- checkpoint status and genuinely unassisted result, if any;
- unresolved source or learning gaps.
