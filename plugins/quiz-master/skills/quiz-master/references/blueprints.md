# Assessment blueprint

Define a table of topic/objective IDs, planned item counts, question types, cognitive targets, and estimated difficulty. Honor explicit requirements. If user requests balanced coverage across N topics, allocate floor(Q/N) to each and distribute remaining slots fairly among eligible topics. Do not silently exclude topics lacking enough source-backed material; report the gap. Sample multiple objectives within each topic where feasible. Treat difficulty labels as provisional until calibrated from student data. Ensure the blueprint matches the actual generated item set.

Include format-specific settings: choice option count; matching left/right counts and reuse policy; ordering item count; blank count, text/numeric kind, units and tolerance. Allocate only to source-supported formats.

## Workload policy
Plan question objects and response units separately. One unit for a single/boolean response, each multiple-choice option decision, each matching pair, each ordering position, and each blank. These are workload bookkeeping, not independent samples or measured duration. Default caps: 20 objects / 50 units; matching4, ordering6, blanks3, options6. Explicit overrides go in the ledger. Show per-type distribution and required/excluded scope. Full-lecture coverage is a goal, not permission to exceed caps or inflate coverage by supplied facts. If it does not fit, show gaps and suggest multiple manageable sessions.
